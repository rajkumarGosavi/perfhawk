# V3 "Explain" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tell the user what to look at, in plain sentences, from deterministic rules (B1), and let them take what they found out of Prism: SVG/PNG of a flame, collapsed-stack text, CSV of tables, and a copyable share link (D4).

**Architecture:** A rule engine in `prism-analysis` (`findings.rs`) runs over a profile with a `RuleConfig` of thresholds and returns scored `Finding`s, each carrying a view patch that opens the evidence. One endpoint serves them; the UI renders a findings panel on the Summary and in a side drawer, with per-rule disabling kept in the browser. Export is pure TypeScript over the data the views already hold.

**Tech Stack:** Rust (`prism-analysis`, `prism-server`), React 19, TypeScript, vitest. **No new dependencies.**

**Spec:** [docs/VISUALIZATION.md](../../VISUALIZATION.md) §4 B1, D4 and §7 (V3). Depends on V2 ([plan](2026-11-13-v2-reduce.md)): uses `groups` (lock/thread rules) and transform chips (`tx`) in finding actions.

## Global Constraints

- No new dependencies. No changes under `crates/prism-capture`, `prism-import`, `prism-store`, `prism-model`, `agents/`, `helpers/`.
- Rules are **deterministic and explainable**: same profile + same config → byte-identical JSON; every finding states the numbers it rests on so the parked AI assistant ([AI.md](../../AI.md)) can cite it.
- A finding never fires on an empty or zero-total profile; no `NaN`/`Infinity` anywhere.
- Findings API returns at most 20 findings, ordered by `score` desc then `id` asc.
- Files use LF endings; stack/tree code is iterative; every control keyboard reachable with an accessible name; no colour-only information (severity is a text label).
- Green after each task: `cargo test --workspace`, `cargo clippy --workspace -- -D warnings`, and in `ui/`: `npm test`, `npm run lint`, `npm run build`.

## Review Focus

- Empty profile, single-sample profile and a profile whose only sample has an empty stack: no findings that divide by zero, no crash, an explicit "too few samples" finding only when `0 < samples < 100`.
- A flat profile (top 10 functions together under 30% self): the engine says so ("no single hotspot") rather than staying silent.
- Two functions tied for the dominant share: ordering is stable (by name) across runs.
- A function name containing regex metacharacters used in a finding's `focus` action is escaped so the action matches only that function.
- Export of a 10 000-deep or 100 000-node tree does not overflow the stack and SVG output escapes `<`, `&` and quotes in function names.

### Task 1: Rule engine core and first four rules (Rust)

**Files:**
- Create: `crates/prism-analysis/src/findings.rs`
- Modify: `crates/prism-analysis/src/lib.rs`
- Test: `crates/prism-analysis/tests/findings.rs`

**Interfaces:**
- Produces:
  - `pub enum Severity { Info, Warn, High }` (serde lowercase).
  - `pub struct Finding { id: String, rule: &'static str, severity: Severity, score: f64, title: String, detail: String, evidence: Evidence, action: FindingAction }` (serde camelCase). `Evidence { func_id: Option<u32>, name: Option<String>, value: i64, pct: f64 }`. `FindingAction { label: String, view: String, func_id: Option<u32>, focus: Option<String>, tx: Option<String>, sort: Option<String>, group_by: Option<String> }` (a serialisable view patch; `focus` is an already-escaped regex).
  - `pub struct RuleConfig` with `Default`: `dominant_self_pct: 30.0`, `flat_top10_pct: 30.0`, `recursion_depth: 50`, `min_samples: 100`, `gc_alloc_pct: 25.0`, `idle_pct: 50.0`, `site_pct: 50.0`, `stack_pct: 50.0`, `alloc_site_pct: 40.0`, `thread_min: 1000`.
  - `pub fn findings(p: &Profile, sample_type: usize, filter: &Filter, cfg: &RuleConfig) -> Vec<Finding>`.
- Rules in this task (ids): `dominant-function` (top self ≥ `dominant_self_pct`; severity High ≥ 60 else Warn; action `view=sandwich` with `func_id`), `flat-profile` (self of top 10 < `flat_top10_pct`; Info; action `view=top`), `deep-recursion` (some function appears ≥ `recursion_depth` times in one stack; Warn; action `tx=rec`), `few-samples` (`0 < samples < min_samples`, counting samples after the filter; Info). `score` = the rule's headline percentage (or a fixed 10 for `few-samples`).

- [ ] **Step 1: Write failing tests** in `tests/findings.rs` (copy the `build` helper pattern from `tests/analysis.rs`): `dominant-function` fires for a 70% leaf with `evidence.pct ≈ 70.0`, severity `High`, `action.func_id` set, and does not fire at 29.9%; `flat-profile` fires for 20 equal leaves and not for the 70% profile; `deep-recursion` fires for a stack with one function repeated 60 times with `action.tx == "rec"`; `few-samples` fires for 5 samples and not for 0 or 100; empty profile → `[]`; a function named `a.b(c)*` produces `focus` equal to the regex-escaped name; identical input twice → identical `serde_json` output; two equal-share functions order by name.

- [ ] **Step 3: Implement** using `top()` for the self/total aggregates and one `for_each_sample` pass for recursion; escape with `regex::escape`; sort and truncate to 20 at the end. Export the items from `lib.rs`.
- [ ] **Step 4: Run** `cargo test --workspace && cargo clippy --workspace -- -D warnings`. Expected: PASS.

### Task 2: Kind-specific rules (Rust)

**Files:**
- Modify: `crates/prism-analysis/src/findings.rs`, `crates/prism-analysis/tests/findings.rs`

**Interfaces:**
- Consumes: Task 1; `groups`, `GroupBy` from V2 (`prism-analysis`).
- Produces: `findings` also evaluates by `p.meta.kind` (`ProfileKind`):
  - `gc-alloc-heavy` (cpu/wall): share of samples whose stack contains a runtime GC or allocator frame ≥ `gc_alloc_pct`. Name patterns (documented in a `const` table): GC `^runtime\.(gcBgMarkWorker|gcDrain|gcAssistAlloc|scanobject|greyobject|markroot|bgsweep|bgscavenge)`; allocator `^runtime\.(mallocgc|newobject|makeslice|growslice|makemap)`; .NET `^(JIT_New|Gen[012] GC|GC_)`. Warn; action `view=flame` with `focus` of the combined pattern.
  - `mostly-idle` (wall): self share of leaf frames named `runtime.gopark`, `runtime.notesleep`, `runtime.futexsleep`, `runtime.netpoll`, `epoll_wait`, `futex_wait`, `pthread_cond_wait` ≥ `idle_pct`; Info; says the profile is mostly waiting.
  - `lock-site-dominant` (lock/blocking): top `Site` group holds ≥ `site_pct` of the primary value; Warn/High ≥ 80; action `view=groups`, `group_by=site`.
  - `stacks-parked` (threads): top identical-stack group holds ≥ `stack_pct` of samples and total count ≥ `thread_min`; Warn; action `view=groups`, `group_by=stack`.
  - `alloc-site-dominant` (memory): top self function holds ≥ `alloc_site_pct` of the default sample type; Warn; action `view=sandwich`.
- [ ] **Step 1: Write failing tests**, one fires / one does-not-fire pair per rule using `ProfileMeta.kind` set accordingly (lock profile with `contentions`+`delay` types; threads profile with 1 500 samples of one stack fires `stacks-parked`, 999 does not); a CPU profile must not emit lock/threads rules and a lock profile must not emit `gc-alloc-heavy`.
- [ ] **Step 2: Run** `cargo test -p prism-analysis --test findings`. Expected: FAIL.
- [ ] **Step 3: Implement** the rules with a per-function memoised regex match (reuse the pattern from `filter.rs`).

## Rulings made while planning

- Thresholds are code defaults in `RuleConfig`; no API or UI tuning (YAGNI until users ask). Rule names target Go and .NET runtime frames; other runtimes get only the language-neutral rules.
- Rule-disable state is browser-local, not stored server-side.
- Findings are computed per request (no caching); they reuse `top`/`groups`, which are already within the interaction budget.
- B1's "profile is empty because mutex profiling is disabled" is not repeated: capture warnings already surface it on the Summary.
