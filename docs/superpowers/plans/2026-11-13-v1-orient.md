# V1 "Orient" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A user opening any profile lands on a summary that says where to look, can jump to the hottest call path in one click or one key, can browse an expandable call tree, and can use the whole profile view from the keyboard.

**Architecture:** UI-only change; no server, store or capture work. All new logic lives in small pure modules under `ui/src/analysis/` (hot path, call tree rows, per-kind guide, headline text, key mapping) that are unit-tested with vitest. React components (`Summary`, `CallTree`, flame highlight, `ProfileView` wiring) are thin shells over those modules, because the UI has no component-test harness.

**Tech Stack:** React 19, TypeScript, Vite, vitest, oxlint (all existing; **no new dependencies**).

**Spec:** [docs/VISUALIZATION.md](../../VISUALIZATION.md) §4 items A1, A2, A3, A6, A8, B2 and §5 (roadmap V1, §7).

## Global Constraints

- No new runtime or dev dependencies (Apache-2.0 / permissive-only rule still holds).
- No changes under `crates/`, `agents/`, `helpers/`. Uses the existing endpoints `/api/profiles/{ref}/flame|top` and `/api/sessions/{ref}` only.
- Files use LF line endings.
- Tree code is **iterative**, never recursive (flame trees can be 1 000 deep by default and 10 000 deep at the cap).
- Every view state is in the URL (shareable); `h` hot-path state is `hot=1`.
- Every view is keyboard reachable; interactive elements have accessible names; no information is colour-only.
- Latency budget (VISUALIZATION.md §6): building rows and hot path for a 50 000-node tree ≤ 100 ms in a vitest timing check; the page never renders more than `maxChildren` (200) children of one node.
- `npm test`, `npm run lint` and `npm run build` (in `ui/`) are green after every task.

## Review Focus

- A profile with zero samples (root `total` 0): summary shows "No samples" text, never `NaN%`/`Infinity%`; hot path is just the root.
- A 10 000-deep chain and a node with 10 000 children: hot path, rows and key navigation neither overflow the stack nor render 10 000 DOM rows.
- Old links with no `view` parameter now open the summary; `view=flame` still opens the flame; an unknown `view` falls back to summary.
- Typing in Focus/Exclude/Hide/Search or the sample-type select never triggers a shortcut; `/` focuses Search without inserting a `/`.
- An imported profile whose kind is unknown (or `unknown` fidelity) gets a generic guide, not a crash or empty page.
- Hot-path ties are deterministic (first child wins), and a hot path ending in a depth-truncated node says so.

**Interfaces:**
- Consumes: `FlameNode` from `ui/src/api.ts`.

  - zero-total children are never entered.
  - 10 000-deep single chain returns 10 001 nodes without throwing.
  - `hotPathEndsTruncated` true/false cases.

### Task 3: Call tree rows

**Files:**
- Create: `ui/src/analysis/callTree.ts`, `ui/src/analysis/callTree.test.ts`

**Interfaces:**
- Consumes: `FlameNode`; `hotPath` from Task 2.
- Produces:
  - `type TreeRow = { kind: 'node'; key: string; node: FlameNode; depth: number; hasChildren: boolean; expanded: boolean } | { kind: 'more'; key: string; depth: number; count: number }`.
  - Node keys are child-index paths joined by `/`; root key is `''`; the "more" row of a node with key `k` has key `k + '/…'`.
  - `visibleRows(root, expanded: ReadonlySet<string>, maxChildren = 200): TreeRow[]` — pre-order, only descends into expanded nodes, shows the first `maxChildren` children then one `more` row with `count` = hidden children.
  - `hotPathKeys(root): { expand: Set<string>; leaf: string }` — keys of every hot-path node that has children (to expand) and the leaf key.
  - `parentKey(key: string): string | null`.
  - `moveSelection(rows: TreeRow[], current: string | null, dir: 'up' | 'down' | 'first' | 'last'): string | null` — skips `more` rows; `null` current + `down` selects the first row; clamps at ends.
  - `toggled(set: ReadonlySet<string>, key: string): Set<string>`.

- [ ] **Step 1: Write failing tests** (`callTree.test.ts`):
  - collapsed root → one row (root); expanded root → root plus its children in order, depths 0 and 1.
  - nested expansion yields pre-order rows with correct `depth`, `hasChildren`, `expanded`.
  - 10 000 children, root expanded → 200 node rows + 1 `more` row with `count 9800`.
  - `hotPathKeys` on `a→[b→[d], c]` returns expand `{'', '0'}` and leaf `'0/0'`.
  - `parentKey('0/2/1') === '0/2'`, `parentKey('0') === ''`, `parentKey('') === null`.
  - `moveSelection` down/up/first/last, clamping, skipping a `more` row, and `null` start.
  - 10 000-deep chain fully expanded builds 10 001 rows without throwing; 50 000-node tree builds in under 100 ms.
- [ ] **Step 2: Run** `cd ui && npx vitest run src/analysis/callTree.test.ts`. Expected: FAIL.
- [ ] **Step 3: Implement** with an explicit stack (push children in reverse for pre-order).
- [ ] **Step 4: Run** the same command. Expected: PASS.
- [ ] **Step 5: Commit** `feat(ui): call tree row model`.

## Rulings made while planning (spec deviations, each recorded in VISUALIZATION.md §7)

- **A6 "left-heavy toggle" dropped:** the server already orders flame children by total (largest first), so the flame is already left-heavy. Only the flame + top "Both" layout ships.
- **A8 trimmed:** `/`, `1–6`, `h`, `?`, call-tree arrows ship; the command palette and `[` `]` zoom history are deferred to V2 (zoom state is internal to `FlameGraph`).
- **A1 trimmed:** "biggest diff movers" on the summary needs a baseline-selection design; deferred to V2 with the diff upgrades (A7).
- **Hot path "next heaviest on repeat" dropped** (YAGNI); one deterministic path.
- **B2 shape:** every kind opens on Summary; the per-kind difference is the guide card (questions + one-click actions such as "Longest waits"). Lock/blocking by-site tables arrive with A9 in V2.
- **Default view change:** links with no `view` previously meant Flame; they now mean Summary (`view=flame` is written explicitly).
