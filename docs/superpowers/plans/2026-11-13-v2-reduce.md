# V2 "Reduce" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a user cut a profile down to what matters without writing regexes (transform chips), compare profiles more usefully (diff call tree, regressions/improvements filter, percent sort, new/gone badges, colour-blind palette, side-by-side), see threads and lock waits grouped the way people reason about them (identical stacks, wait sites), and jump from a function to the same function in the other profiles of its session.

**Architecture:** Server-side: transforms become part of the existing `Filter` and run inside `for_each_sample`, so flame, top, sandwich, diff and groups all honour them with no extra code per view. Two new read-only analyses (`groups`, `function_stats`) and two new endpoints (`/groups`, `/sessions/{ref}/pivot`) are added; diff top gains a sort option. UI-side: small pure modules (transform encoding, diff tree helpers) carry the logic and are unit-tested; React components stay thin shells.

**Tech Stack:** Rust (axum, existing crates `prism-analysis`, `prism-server`), React 19, TypeScript, Vite, vitest, oxlint. **No new dependencies** in either language.

**Spec:** [docs/VISUALIZATION.md](../../VISUALIZATION.md) §4 items A5, A7, A9, B3 and §7 (roadmap V2). Builds on V1 ([plan](2026-11-13-v1-orient.md), merged).

## Global Constraints

- No new Cargo or npm dependencies (Apache-2.0 / permissive-only rule holds).
- No changes under `agents/`, `helpers/`, `crates/prism-capture`, `crates/prism-import`, `crates/prism-store`, `crates/prism-model` (no capture or data-model work).
- Files use LF line endings. Tree/stack code is iterative, never recursive.
- Every view state is in the URL; every new control is keyboard reachable with an accessible name; no information is colour-only.
- Performance (VISUALIZATION.md §6): transforms re-run ≤ 300 ms on a 1M-sample profile (checked manually in Task 9, not as a timing test); responses never return more than 1 000 rows (`limit` is clamped).
- Wire format for transforms: query/URL parameter `tx`, a comma-separated list of `kind` or `kind:payload` items applied left to right; `payload` is percent-encoded (JavaScript `encodeURIComponent` semantics, so `,` `:` `%` never appear raw inside a payload). At most 32 items.
- `cargo test --workspace`, `cargo clippy --workspace -- -D warnings`, and (in `ui/`) `npm test`, `npm run lint`, `npm run build` are green after every task that touches that side.

## Review Focus

- Function names containing `,` `:` `%` `/` or spaces survive `tx` encoding on both sides (Task 1 Rust test, Task 4 TS test).
- A `sub:` transform naming a function absent from the profile yields an empty result (root total 0): the server returns it without error and the UI shows "No samples in this view.", never `NaN%` (Tasks 1, 4).
- Pivot for a function that does not exist in a sibling profile gives `found: false` for that profile, not an error; a session with a single profile shows no pivot panel (Tasks 3, 8).
- Groups on a profile with 100 000 distinct stacks returns at most `limit` rows (default 100, max 1 000) and mean is `null` when the count is 0 (Task 5).
- Diff on two identical profiles, or empty profiles: filters, percent sort and side-by-side render no rows and no `NaN`/`Infinity`; rows new in head (base 0) sort first under percent sort (Tasks 6, 7).

**Files:**

- Modify: `crates/prism-analysis/src/lib.rs`, `crates/prism-analysis/src/filter.rs`, `crates/prism-analysis/tests/analysis.rs`

**Interfaces:**
- Produces:
  - `pub enum Transform { FocusSubtree(String), Merge(String), Drop(String), CollapseRecursion, CollapsePackage }` (derive `Debug, Clone, PartialEq`).
  - `pub fn parse_transforms(s: &str) -> Result<Vec<Transform>, TransformError>`; `TransformError` is a `thiserror` enum whose `Display` names the bad item (unknown kind, missing or empty payload, payload on `rec`/`pkg`, bad percent escape, more than 32 items). Empty string → `Ok(vec![])`.
  - `pub fn package_of(name: &str) -> &str`.
  - `Filter` gains `pub transforms: Vec<Transform>`; `Filter::parse` keeps its signature (transforms empty); add `pub fn with_transforms(self, t: Vec<Transform>) -> Filter`. `Filter::is_empty()` is false when transforms exist (so the unfiltered fast path in `tree.rs` is skipped).
  - `for_each_sample` applies transforms after exclude, focus, hide, in list order.
- Semantics (names match exactly, ignoring file):
  - `FocusSubtree(n)`: drop the sample if no frame is named `n`; otherwise cut the stack to start at the outermost frame named `n`.
  - `Merge(n)`: remove every frame named `n`, keep the sample.
  - `Drop(n)`: drop samples containing a frame named `n`.
  - `CollapseRecursion`: replace each run of adjacent identical functions with one.
  - `CollapsePackage`: replace each run of adjacent frames with the same `package_of` by the first frame of the run (the entry into the package; the node keeps that function's name).
- `package_of`: contains `/` → text before the first `.` after the last `/` (whole name if no `.`); else split on `.`: 1 segment → the name; 2 segments, or ≥ 3 where the second starts with `(` → the first segment; ≥ 3 otherwise → all but the last two segments joined by `.`.

## Rulings made while planning (spec deviations, each recorded in VISUALIZATION.md §7)

- **A5 trimmed:** "collapse by package" keeps the entry frame of each same-package run instead of synthesising a package node (frames carry function ids; synthetic nodes would need a data-model change). `package_of` is a heuristic (Go paths, .NET namespaces); `main.T.run.func1`-style names may group at `main.T`. Indirect recursion is not collapsed. Matching is exact function name, not name+file.
- **A5 entry points:** chips are added from the call tree (`f m x`), a manual add row, and the two global toggles; Top-table and flame-click entry points are deferred.
- **A7 trimmed:** the regressions/improvements filter uses self delta for tables and total delta for trees; percent sort is server-side (before the row limit); side-by-side shares one diff request and does not link zoom between the two graphs.
- **A9 trimmed:** no goroutine *state* column (the model has no state data); "site" is the innermost non-`runtime.`/`sync.`/`internal/` frame (Go-centric; .NET lock profiles fall back to the leaf frame); "who holds it" is out of scope.
- **B3 shape:** pivot compares each profile's default sample type by function name; it is shown in Sandwich and on the Summary, not as a separate page.
