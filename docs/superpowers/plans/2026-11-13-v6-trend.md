# V6 "Trend" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Answer "did it get slower over time?" with a History view (a function's cost across the sessions of one target, click a point to open or diff that session) and a CI-friendly command, `prism check`, that compares a profile against a baseline and exits non-zero when a function regresses beyond a threshold.

**Architecture:** Sessions are grouped into **series** by a tag (`series:<name>`) or, when absent, by a key derived from the target (`<runtime>:<command or url>`). A new `prism-analysis::history` computes per-session function stats using the existing `function_stats` (V2); the server exposes `/api/series` and `/api/history`; the UI draws an accessible line chart with a data table. `prism check` reuses `diff_top_sorted` and prints a table plus an exit code; it adds no server dependency.

**Tech Stack:** Rust (`prism-analysis`, `prism-server`, `prism-cli`, `prism-store` read-only), React 19, TypeScript, SVG, vitest. **No new dependencies.**

**Spec:** [docs/VISUALIZATION.md](../../VISUALIZATION.md) §4 C4, §7 (V6); [docs/PLAN.md](../../PLAN.md) §5.2 (CI regression gating). Builds on V2 ([plan](2026-11-13-v2-reduce.md)): `function_stats`, `diff_top_sorted`.

## Global Constraints

- No new dependencies. No changes to capture crates, importers, `agents/`, `helpers/`, or the stored profile/session schema (series come from existing tags and target fields; `prism record --tag series:x` already works).
- A series is ordered by session `started_at_unix_ms` ascending; at most 200 points are returned per request (most recent kept).
- `prism check` exit codes: `0` no regression, `1` regression found, `2` usage/data error (unknown profile, no common sample type, bad threshold). Output is deterministic; `--json` prints the same data machine-readably.
- Threshold semantics (documented in `--help`): a function **regresses** when its self value grows by more than `--threshold` percent (default 10) **and** by at least `--min-value` of the head total's percentage (default 1.0 percent-of-total points); functions new in head count as regressions when their self ≥ `--min-value` points of total. Improvements never fail the check.
- Files use LF endings; UI controls keyboard operable; chart has a text equivalent (data table) and no colour-only meaning.
- Green after each task: `cargo test --workspace`, `cargo clippy --workspace -- -D warnings`, and in `ui/`: `npm test`, `npm run lint`, `npm run build`.

## Review Focus

- Sessions of one target where some have no profile of the requested kind, or the function is absent in some: those points are present with `found: false` and the chart shows a gap, not a zero.
- A series with a single session: History shows the point and "Need at least 2 sessions to show a trend", no crash.
- `prism check` with identical profiles exits 0; with base empty (total 0) it exits 2 with a clear message rather than dividing by zero; a function renamed between runs shows as one improvement and one regression.
- Sample types: profiles that do not share the requested sample type are skipped with a reason in the response, and `prism check` without `--sample-type` uses the common default (exit 2 if none).
- Series keys containing `:` or non-ASCII characters round-trip through the URL.

**Interfaces:**

Exit codes per Global Constraints. Percent-of-total points are computed from each side's own total so runs of different length compare fairly.

## Rulings made while planning

- **Series by tag, not by new schema:** `series:<name>` tags (already supported by `--tag`) plus a derived fallback key avoid a store migration. A future "rename series" feature would need real storage.
- **Function identity is the exact name**, so a rename shows as one improvement and one regression; no fuzzy matching.
- **`prism check` is local-only:** it reads the local store (or imported files); there is no PR commenting, dashboard or share server (Phase 4).
- **History uses each profile's own default sample type unless `st` is given**; mismatches are reported per point instead of failing the whole request.
