# Phase 2 M3: ETW Provider (Windows) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Windows `SystemProvider` that captures Block I/O, off-CPU and scheduler-delay profiles with symbolized stacks for one target process, so `perfhawk record --kind block-io,off-cpu,sched-delay` and `perfhawk doctor` give firm I/O verdicts for Go and .NET.

**Architecture:** A new Windows-only module tree `crates/perfhawk-capture/src/etw/` implements the existing `SystemProvider` trait (Phase 2a, `system.rs`). Raw ETW events are decoded into plain structs (`RawEvent`), then a pure aggregator turns them plus a symbolizer into `EventRow`s, which the existing `event_artifact` encodes. Everything between "ETW callback" and "Artifact" is pure and unit-tested with synthetic events; only the session wrapper and the final e2e need Windows admin.

**Tech Stack:** Rust, `ferrisetw` (ETW consumer, MIT/Apache-2.0) or the `windows` crate where ferrisetw lacks an API (decided in Task 1), `object` (symbol tables), existing `perfhawk-capture`, `perfhawk-model`, Go demo app, .NET demo app.

**Spec:** [docs/superpowers/specs/2026-11-13-phase2-contention-io-design.md](../specs/2026-11-13-phase2-contention-io-design.md) §7.1 M3, §7.2, §7.3, §10. Builds on [2026-11-13-phase2a-core-doctor.md](2026-11-13-phase2a-core-doctor.md) (merged).

## Global Constraints

- Targets: Go 1.22+, .NET 8+; Windows 10/11 x64 for M3. New dependencies must be permissively licensed (`cargo deny check licenses` stays green).
- Perfhawk never self-elevates. A missing privilege is reported in `Capability.note` with the exact elevated command; no `runas`, no UAC prompt.
- Capture is scoped to one target process (and its threads); no whole-system output is stored.
- Block I/O profile: sample types `io_time` (ns, default) then `io_bytes` (bytes); file is the synthetic leaf frame `file_leaf(path)`. Off-CPU: `offcpu` (ns). Scheduler: `sched_delay` (ns). Fidelity `Native` for ETW data; frames that are not symbolized make the artifact carry a warning, not a different fidelity.
- Timestamps: ETW QPC times are converted to wall-clock UTC at capture start (spec §10 "Alignment"). The captured window and `start_unix_ns` match the language provider's window.
- Process exit ends the capture with `CaptureEnd::TargetExited`; Ctrl-C ends it with `Cancelled`. In both cases the partial data is still returned.
- Symbolization bar (spec §10): required = Go frames from unstripped binaries and .NET JIT-compiled methods; allowed fallback = `module+0xoffset`; stripped Go binaries are reported as such. No PDB/DbgHelp dependency in M3 (module+offset is the allowed fallback; PDB is a FOLLOWUP).
- Overhead text is static (`SystemProvider::overhead`) and printed before capture along with the duration cap. No calibration.
- Real-ETW tests are `#[ignore]` and gated on `PERFHAWK_ETW=1`; they require an elevated shell. Normal `cargo test --workspace` must pass non-elevated.
- The whole `etw` module is `#[cfg(windows)]`; the pure decode/aggregate/symbolize code is NOT cfg-gated so it is tested on every OS in CI.

## Review Focus

1. **Non-elevated run.** `perfhawk record --kind block-io` without admin → a clear "run from an elevated shell: `<exact command>`" error, no crash, no partial session left `running`. Language profiles in a mixed request still succeed (session `Partial`). (Task 6)
2. **Another trace owns the NT Kernel Logger** (ETW allows one such session per machine; Windows Performance Recorder, PerfView and Visual Studio use it). Perfhawk must not kill it; it reports who/what is likely holding it and fails cleanly. A stale Perfhawk session from a crashed run is stopped on the next start. (Task 1, Task 6)
3. **Target exits mid-capture, or pid is reused** after exit: `TargetExited` with data captured so far; events from a different process image are ignored by (pid, process start time). (Task 3, Task 6)
4. **Event loss.** ETW drops events under load (`EventsLost`, `RealTimeBuffersLost`). The artifact gets a warning with the loss count; Doctor must not read a lossy profile as a firm verdict. (Task 3)
5. **Unsymbolizable stacks** (stripped Go binary, JIT code with no rundown, missing module): frames fall back to `module+0xoffset` or `[unknown]`, never an empty stack, never a panic, and a warning says how many frames were unresolved. (Task 4, Task 5)

### Task 2: Time conversion and event aggregation (pure)

**Files:**
- Modify: `crates/perfhawk-capture/src/sysevents.rs`, `crates/perfhawk-capture/src/lib.rs`
- Test: `crates/perfhawk-capture/tests/etw_aggregate.rs`

**Interfaces:**
- Consumes: `RawEvent`, `RawKind` (Task 1); `EventRow`, `EventSpec`, `event_artifact` (`events.rs`, Phase 2a); `file_leaf` (`perfhawk-model`).
- Produces:
  - `pub struct QpcClock { pub freq: i64, pub qpc_start: i64, pub unix_start_ns: i64 }` with `pub fn to_unix_ns(&self, qpc: i64) -> i64` and `pub fn qpc_to_ns(&self, delta: i64) -> u64`.
  - `pub struct AggregateInput<'a> { pub events: &'a [RawEvent], pub target_pid: u32, pub clock: QpcClock, pub window_ns: u64, pub bucket_ns: u64, pub symbolize: &'a dyn Fn(&RawEvent) -> Vec<String> }`
  - `pub struct Aggregated { pub block_io: Vec<EventRow>, pub off_cpu: Vec<EventRow>, pub sched_delay: Vec<EventRow>, pub unresolved_frames: u64 }`
  - `pub fn aggregate(input: &AggregateInput) -> Aggregated`

Semantics `aggregate` must implement:
- **Block I/O:** one row per `FileRead`/`FileWrite` of the target: `stack = symbolize(ev)` (root-first) plus `file_leaf(path)`, `values = [duration_ns, bytes]`. A disk event with no matching file event (same tid, overlapping time) becomes a row whose leaf is `file_leaf("[disk]")`.
- **Off-CPU:** for each target thread, the span from its switch-out (`CSwitch` with `old_tid`) to its next switch-in (`new_tid`); stack is the switch-out event's stack; `values = [span_ns]`. A span still open at the end of the window is closed at `window_ns`. Spans shorter than 1 µs are dropped.
- **Scheduler delay:** for each `ReadyThread` of a target thread, from the ready event to that thread's next switch-in; stack is the readier's stack; `values = [delay_ns]`.
- `bucket = (event time − window start) / bucket_ns`, clamped to the last bucket; events outside the window are dropped.

- [ ] **Step 1: Write failing tests** in `etw_aggregate.rs`: `qpc_converts_to_unix_ns` (freq 10_000_000, delta 10_000_000 → +1_000_000_000 ns); `file_write_becomes_block_io_row_with_file_leaf` (expects last stack frame `file_leaf("C:\\data\\x.db")`, values `[2_000_000, 4096]`); `off_cpu_span_runs_from_switch_out_to_switch_in` (1.5 ms, correct stack); `open_off_cpu_span_is_closed_at_window_end`; `short_spans_are_dropped`; `ready_thread_to_switch_in_is_sched_delay`; `events_of_other_pids_are_ignored`; `events_outside_window_are_dropped`; `bucket_clamps_to_last_bucket`; `disk_event_without_file_gets_disk_leaf`.
- [ ] **Step 2: Run** `cargo test -p perfhawk-capture --test etw_aggregate`. Expected: FAIL (items not defined).
- [ ] **Step 3: Implement `QpcClock` and `aggregate`** in `sysevents.rs`. Per-thread open-span state in an `FxHashMap<u32, OpenSpan>`; sort events by `qpc` first (ETW delivery is not strictly ordered across CPUs).
