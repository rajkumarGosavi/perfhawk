# V4 "Graph" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A call graph view (the `go tool pprof -http` "Graph"): functions as nodes sized and coloured by self/total, caller→callee edges weighted by flow, dotted edges where intermediate frames were elided, a node-count slider, pan/zoom, and full keyboard navigation.

**Architecture:** The server aggregates edges from stacks for the top-N functions by total (`prism-analysis::graph`), honouring all filters and V2 transforms. The browser lays the graph out with a small in-house layered-graph algorithm (`ui/src/graph/layout.ts`, pure and unit-tested) and draws it as SVG. No Graphviz, no layout library (answers VISUALIZATION.md §9 Q1: in-house; the algorithm is ~200 lines and keeps the permissive-only licence rule trivially true).

**Tech Stack:** Rust (`prism-analysis`, `prism-server`), React 19, TypeScript, SVG, vitest. **No new dependencies.**

**Spec:** [docs/VISUALIZATION.md](../../VISUALIZATION.md) §4 A4, §6 (call graph ≤ 1 s for 1 M samples at default node count), §7 (V4). Builds on V2 ([plan](2026-11-13-v2-reduce.md)).

## Global Constraints

- No new dependencies. No changes under capture/import/store/model crates, `agents/`, `helpers/`.
- Default node count 80, maximum 300 (`nodes` parameter; larger values are clamped). Edge count is bounded by `nodes²` but in practice ≤ 4 × nodes; the response also reports `hiddenNodes` and `totalValue`.
- Layout of 300 nodes / 1 200 edges completes in ≤ 300 ms in a vitest timing check (generous CI margin: assert < 300 ms on a developer machine, log the figure).
- All traversals iterative (graphs may contain cycles and 10 000-deep chains); recursion/cycles never hang or overflow.
- Every view state in the URL; the graph is keyboard operable and each node has an accessible name with its numbers; edges are `aria-hidden` with the selected node's callers/callees listed as text; nothing is colour-only.
- Green after each task: `cargo test --workspace`, `cargo clippy --workspace -- -D warnings`, and in `ui/`: `npm test`, `npm run lint`, `npm run build`.

## Review Focus

- Mutual recursion (`a→b→a`) and self-recursion (`a→a`): no hang, no duplicated edge weights; self-edges are dropped from the graph and reflected only in the node's totals.
- A function appearing several times in one stack contributes each distinct caller→callee pair once per sample.
- Empty profile or zero-total filter result: the view says "No samples in this view." with no division by zero.
- One node with 5 000 distinct callers (clamped by `nodes`) and a 10 000-deep chain: server and layout finish; the SVG never holds more than `nodes` node elements.
- Function names with `<`, `&`, quotes render as text (React escaping), and very long names are truncated visually while the full name stays in the accessible label.

### Task 1: Graph analysis (Rust)

**Files:**
- Create: `crates/prism-analysis/src/graph.rs`
- Modify: `crates/prism-analysis/src/lib.rs`
- Test: `crates/prism-analysis/tests/graph.rs`

**Interfaces:**
- Produces:
  - `pub struct GraphNode { func_id: u32, name: String, file: String, self_value: i64, total: i64 }`; `pub struct GraphEdge { from: u32, to: u32, value: i64, elided: bool }` (`from`/`to` are `func_id`s of selected nodes); `pub struct CallGraph { nodes: Vec<GraphNode>, edges: Vec<GraphEdge>, hidden_nodes: usize, total_value: i64 }` (serde camelCase).
  - `pub fn call_graph(p: &Profile, sample_type: usize, filter: &Filter, max_nodes: usize) -> CallGraph`.
- Semantics: pass 1 computes per-function self/total like `top` and selects the `max_nodes` functions with the largest total (ties: larger self, then name, then id). Pass 2, per sample: take the stack's selected functions in root-first order, collapse consecutive duplicates, and for each adjacent selected pair `(a, b)` with `a ≠ b` add the sample value to edge `a→b` once per sample; the edge is `elided` when any unselected frame (or a dropped duplicate loop) lay between them in that sample and **all** samples contributing to the edge were gapped (a single directly-adjacent contribution makes it non-elided). Nodes sort by total desc then name; edges by value desc then (from, to). `hidden_nodes = distinct functions − nodes.len()`.

- [ ] **Step 1: Write failing tests**: direct chain `a→b→c` yields edges `a→b`, `b→c` with the sample value and none elided; with `max_nodes = 2` on that chain (all totals tie, so the tie-break selects `c` by self then `a` by name) the single edge `a→c` exists and is marked `elided` because `b` lay between them; a function twice in one stack (`a,b,a,b`) adds `a→b` once; self recursion `a,a` yields no edge and `a.total` counted once; mutual recursion `a,b,a` gives `a→b` and `b→a` each once; edge values sum across samples; filter and `sub:` transform respected; empty profile → empty graph with `total_value 0`; tie ordering deterministic; 100 000 distinct functions with `max_nodes 300` returns 300 nodes and a correct `hidden_nodes`.
- [ ] **Step 2: Run** `cargo test -p prism-analysis --test graph`. Expected: compile FAIL.
- [ ] **Step 3: Implement** using `function_totals` from `tree.rs` for pass 1 and `for_each_sample` for pass 2 (a `Vec<bool>` selected-mask; edges in a `FxHashMap<(u32,u32), (i64, bool)>`).
- [ ] **Step 4: Run** `cargo test --workspace && cargo clippy --workspace -- -D warnings`. Expected: PASS.
- [ ] **Step 5: Commit** `feat(analysis): call graph aggregation`.

### Task 3: Layered layout (TypeScript, pure)

**Files:**
- Create: `ui/src/graph/layout.ts`, `ui/src/graph/layout.test.ts`

**Interfaces:**
- Produces:
  - `type LNode = { id: number; w: number; h: number }`, `type LEdge = { from: number; to: number; weight: number }`.
  - `type Placed = { id: number; x: number; y: number; layer: number }` (x,y = top-left); `type Route = { from: number; to: number; points: [number, number][]; reversed: boolean }` (a polyline/Bézier control path, from the source's bottom centre to the target's top centre, passing through dummy positions for edges spanning several layers; `reversed` marks edges that were flipped to break a cycle).
  - `layoutGraph(nodes: LNode[], edges: LEdge[], opts?: { layerGap?: number; nodeGap?: number; sweeps?: number }): { nodes: Placed[]; routes: Route[]; width: number; height: number }` — deterministic. Steps: ignore self-edges and edges naming unknown nodes; break cycles by reversing DFS back edges (iterative DFS, nodes visited in input order); layer = longest path from sources; insert dummy nodes for long edges; order each layer by barycentre over `sweeps` (default 4) down/up passes with a stable tiebreak on input index; place x by packing left-to-right with `nodeGap` and centring each layer; `y = layer × (maxHeight + layerGap)`.
- [ ] **Step 1: Write failing tests**: chain of 3 → layers 0,1,2 and strictly increasing y; diamond `a→b,a→c,b→d,c→d` puts `b`,`c` in one layer without overlapping boxes (x ranges disjoint by ≥ `nodeGap`); cycle `a→b→a` terminates with exactly one route `reversed`; self-edge ignored; edge spanning 3 layers has ≥ 4 route points; two disconnected components both placed, no overlap; identical input twice → identical output; empty input → zero size; 300 nodes / 1 200 random-but-seeded edges lays out in < 300 ms with no overlapping boxes within a layer; a 10 000-node chain does not throw.
- [ ] **Step 2: Run** `cd ui && npx vitest run src/graph/layout.test.ts`. Expected: FAIL.

## Rulings made while planning

- In-house layout instead of an embedded library (closes VISUALIZATION.md §9 Q1). Quality target is "readable for ≤ 300 nodes", not Graphviz-grade crossing minimisation; the layout module is isolated so a library could replace it later without touching the server or the view.
- Node selection is by total, so a function with tiny total but high self cannot appear if larger-total functions fill the budget; the slider is the escape hatch.
- Graph and diff are separate: no differential graph in V4.
- The graph is a static layout of a fixed node set; drag-to-rearrange nodes is out of scope.
